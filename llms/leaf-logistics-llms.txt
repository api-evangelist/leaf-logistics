# Leaf Logistics

> Leaf Logistics Inc. is a New York-based freight coordination platform for shippers, carriers and
> brokers. Leaf builds multi-shipper circuits and multi-shipper dedicated "Flex Fleets" so freight can
> be scheduled months in advance under long-term contracts, cutting empty miles, rate volatility and
> Scope 3 emissions. Generated by API Evangelist from probed public sources — Leaf publishes no
> llms.txt of its own (403 on www.leaflogistics.com/llms.txt, 404 on api.leaflogistics.com/llms.txt).

## API surface

- [Leaf Logistics Platform API](https://api.leaflogistics.com/v1/graphql): GraphQL endpoint served by
  Hasura GraphQL Engine v2.35.1. Runs in JWT authentication mode — an anonymous request returns
  "Missing 'Authorization' or 'Cookie' header in JWT authentication mode", so schema introspection is
  gated and no SDL could be retrieved.
- [Hasura REST endpoint namespace](https://api.leaflogistics.com/api/rest): same JWT gate.
- [Engine version](https://api.leaflogistics.com/v1/version): anonymous, returns
  {"server_type":"ce","version":"v2.35.1"}.
- [Health check](https://api.leaflogistics.com/healthz): anonymous, returns OK.

## What is NOT published

- No OpenAPI, Swagger, AsyncAPI, GraphQL SDL or Postman collection on any Leaf host.
- No developer portal, API reference, getting-started guide or authentication documentation.
- No public pricing or plans; no self-service signup for API access.
- No MCP server, no A2A agent card, no /.well-known/ documents, no security.txt.
- No SDKs or client libraries in any package registry; no GitHub organization.
- No status page, changelog, deprecation policy or published rate limits.

Integration is arranged through Leaf's onboarding motion. Leaf's shipper FAQ states it will work
"through email, phone, fax, EDI, API — whatever you prefer".
